# PromptOptimizer (가칭) PRD v1.0 — 규칙/템플릿 기반 프롬프트 최적화 (No Backend)

작성일: 2026-01-31  
상태: 개발 착수용 (MVP 확정: 요약/마케팅카피/이메일, 기본 Lite)

---

## 1. 개요

### 1.1 서비스명
PromptOptimizer (가칭)

### 1.2 미션
사용자가 입력한 원본 프롬프트를 선택한 모델(OpenAI/Claude/Gemini)에 맞춰 **규칙+템플릿으로 구조화/명확화/제약화**하여, 결과 품질과 일관성을 높이는 “복사 즉시 사용” 프롬프트로 변환하는 웹 도구.

### 1.3 제품 포지션
- LLM 호출 없이 동작하는 **Client-side Prompt Transformer**
- 프롬프트 “문장 재작성”이 아니라, **컨텍스트 엔지니어링 요소(역할/맥락/지시/제약/출력형식/자기검토)를 자동 세팅**하는 도구

---

## 2. 배경 및 문제

- 모델별로 선호하는 프롬프트 구조가 다름
  - Google: Role → Context → Instruction, 제약, 단계 분해, 자기검토
  - Microsoft(Azure OpenAI): 메시지 구성요소 사고, Double Down(중요 지시 반복), 안전 출구(“정보 없음”), 토큰 최적화
  - OpenAI: 지시 상단, 구체화, 출력 템플릿/예시
  - Claude: XML 태그로 섹션 구분, 스타일 일치, 체인(단계 분리)
  - Meta(Llama): 간결함, 제약, 군더더기 제거 (MVP 제외 가능)
- 일반 사용자가 이를 매번 적용하기 어려움

---

## 3. 목표 / 비목표

### 3.1 목표 (Goals)
- 입력 프롬프트를 모델별 권장 구조로 자동 변환
- 모호한 요청(“짧게”)을 UI 옵션으로 구체화
- Before/After + Diff + 적용 태그로 “왜 좋아졌는지” 설명
- 무료 배포를 위해 **No Backend / No LLM API**로 구현 (입력은 서버로 전송되지 않음)

### 3.2 비목표 (Non-goals, MVP 제외)
- LLM 기반 의미 재작성(Rewrite)
- 최적화 프롬프트를 실제 모델에 실행해 결과까지 비교
- 로그인/팀/공유 커뮤니티/파일 업로드/RAG

## 4. 타겟 사용자

- 파워유저: 모델별 템플릿을 빠르게 맞추고 싶음
- 개발자/분석가: 출력 형식(JSON/표) 제어를 강화하고 싶음

## 6. 핵심 원칙 (제품 신뢰 규칙)

1) Intent 보존: 사용자가 말하지 않은 목표/사실을 추가하지 않는다.  
2) 가정 최소화: 정보 부족 시 “가정”을 강요하지 않고, 빈칸은 입력 폼/체크리스트로 보완.  
3) 추론(CoT) 노출 강제 금지: 대신 Self-check(체크리스트) 섹션 제공.  
4) 프라이버시: 입력은 서버로 보내지 않는다(분석 도구 사용 시에도 원문은 전송하지 않는 정책).

## 7. 사용자 플로우

1) 모델 선택  
2) 원본 프롬프트 입력 (또는 샘플)  
3) 옵션 선택 (길이/톤/출력 형식 등)  
4) 최적화하기  
5) 결과 확인 (Before/After, Diff, 적용 태그)  
6) 복사/다운로드  
7) (선택) 로컬 히스토리에서 재사용

## 8. 기능 요구사항 (FR) 및 수용 기준 (AC)

### FR-01 모델 선택
- AC: 선택 모델에 따라 렌더링 구조가 바뀐다(OpenAI=Instruction first, Gemini=Role/Context/Instruction, Claude=XML tags).

### FR-02 원본 프롬프트 입력
- AC: 0자면 실행 불가, 글자 수 표시, 샘플 10개+ 제공.

### FR-03 옵션 패널
옵션(최소):
- 산출물 타입: summary / marketing_copy / email_reply
- 길이: very_short / short / medium (또는 2문장/3문장/5문장/200자/500자)
- 톤: formal / neutral / friendly / persuasive
- 출력 형식: plain / markdown / json
- 안전 출구: 정보 없으면 “정보 없음” (기본 ON)
- 자기검토 체크리스트: 기본 ON
- AC: 옵션 변경이 결과에 반영된다.

### FR-04 최적화 엔진 (클라이언트)
- AC: 공통 규칙 → 타입 템플릿 → 모델 렌더러 순으로 적용된다.
- AC: 결과에 최소 섹션(역할/맥락/지시/제약/출력 형식/자기검토)이 포함된다(Lite는 축약 가능).
- AC: “불필요한 서두 제거” 규칙이 포함된다(템플릿에 명시).

### FR-05 Before/After + Diff + 태그
- AC: Diff 토글 시 추가된 섹션을 하이라이트(문장/블록 단위).
- AC: 적용 태그 표시(#구조화 #제약조건 #자기검토 #안전출구 #모델맞춤 등)

### FR-06 복사/다운로드
- AC: After 원클릭 복사, .txt 다운로드, 선택 시 .md/.json 다운로드.

### FR-07 토큰/길이 추정
- AC: 입력/출력 토큰 근사치 표시, 모델별 컨텍스트 한도 80% 이상 시 경고.

### FR-08 민감정보 경고/마스킹 (로컬)
- AC: 이메일/전화번호/주민번호/키 패턴 감지 시 경고.
- AC: 마스킹된 버전으로 결과 생성 가능.

### FR-09 로컬 히스토리 (권장)
- AC: localStorage에 최근 10개 저장/불러오기/삭제.
