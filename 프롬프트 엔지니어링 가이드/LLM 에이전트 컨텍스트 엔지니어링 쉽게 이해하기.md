# **📘 LLM 에이전트 컨텍스트 엔지니어링 쉽게 이해하기**

## **1\. 컨셉**

* **프롬프트 엔지니어링**: 한 번 질문할 때 문장을 잘 쓰는 기술  
   → 예: “3문장으로 요약해줘.”

* **컨텍스트 엔지니어링**: 질문 \*\*앞뒤에 필요한 정보(역할, 규칙, 기억, 자료, 도구)\*\*까지 설계해서 넣는 기술  
   → 예: “넌 일정 도우미야. 지금까지 대화 요약은 이렇고, 이 도구들을 쓸 수 있어. 이제 질문에 답해.”

👉 비유:

* **프롬프트**는 “질문 하나 잘하기”

* **컨텍스트**는 “시험지에 참고자료, 계산기, 규칙까지 세팅해주기”

---

## **2\. 왜 필요한가?**

* **토큰(메모리) 한도**: 모든 대화를 다 넣을 수 없어서 → 꼭 필요한 것만 요약/선택

* **실수 방지**: 맥락 없으면 AI가 추측(환각) → 컨텍스트로 가이드 필요

* **일관성 유지**: 긴 대화나 장기 작업에서 흐름 끊기지 않게

* **비용 절약**: 불필요한 데이터 줄이면 속도/비용도 줄어듦

👉 예시:

* 컨텍스트 없이 “내일 시간 있어?” \= AI는 그냥 “있습니다.”

* 컨텍스트 포함: 캘린더 조회 → “내일 오전 10시에 회의, 나머지는 비어있습니다.”

---

## **3\. 컨텍스트에 들어가는 것들**

1. **시스템 지시**: “넌 변호사야, 답변은 신중하게 해.”

2. **사용자 질문**: “계약서에 필요한 항목이 뭐야?”

3. **단기 메모리**: 최근 대화 내용 (ex: 직전에 ‘임대차 계약서’ 얘기)

4. **장기 메모리**: 과거 사실 (ex: 이 사용자는 주거용 계약만 관심 있음)

5. **외부 지식**: 최신 법률 자료 검색 결과

6. **툴 설명**: 캘린더, 계산기, 검색 API 같은 사용 가능 도구

7. **툴 결과**: 도구 실행 후 나온 값 (ex: 오늘 날씨 25도)

8. **출력 형식**: JSON, 표, 글 형식 등

---

## **4\. 핵심 기법 4가지**

* **쓰기(Write)**: 중간 생각을 기록해두기  
   → 예: “계획: 먼저 검색 → 요약 → 답변”

* **선택(Select)**: 긴 문서 중 필요한 청크만 뽑기

* **압축(Compress)**: 장황한 내용 요약해서 핵심만 남기기

* **분리(Isolate)**: 서로 다른 역할/단계를 구분해서 맥락 충돌 방지

---

## **5\. 실수 방지 규칙**

* 모르면 → \*\*“정보 없음”\*\*이라고 하게 만들기

* 충돌 정보 → **우선순위 정하기** (시스템 규칙 \> 검색 결과 \> 사용자 말)

* 불필요한 말 → **포맷 강제하기** (예: JSON, 표)

* 긴 대화 → **중요 지시는 앞뒤에 반복**

---

## **6\. 간단한 템플릿 예시**

**시스템 지시**

넌 일정 관리 도우미야.    
답변은 JSON으로만.    
모르면 "정보 없음"이라고 해.  

**출력 JSON 예시**

{  
  "answer": "내일 10시 회의 있음",  
  "evidence": \["cal://2025-09-23"\],  
  "next\_actions": \["오후 2시에 약속 가능"\]  
}

---

## **7\. 실제 적용 예시**

**사용자**: “내일 시간 있어?”  
 **컨텍스트 세팅**:

* 시스템 지시: 일정 도우미

* 단기 메모리: 직전 대화에서 “내일 미팅 잡자”

* 장기 메모리: 이 사용자는 오전보다는 오후 선호

* 툴: 캘린더 조회 API

**결과**:  
 “내일 오전 10시에 팀 미팅 있고, 오후는 비어 있습니다.”

---

👉 정리:  
 컨텍스트 엔지니어링은 **AI가 답을 더 똑똑하게 하도록 ‘시험 환경’을 만들어주는 기술**

* 프롬프트 \= 질문 잘하기

* 컨텍스트 \= 시험지, 규칙, 도구 다 깔아주기
