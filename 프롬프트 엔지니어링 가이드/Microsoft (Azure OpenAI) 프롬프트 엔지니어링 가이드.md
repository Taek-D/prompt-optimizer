# **📘 Microsoft (Azure OpenAI) 프롬프트 엔지니어링 가이드**

Microsoft는 Azure OpenAI를 사용하는 개발자들을 위해 **프롬프트를 설계하는 방법과 원칙**을 정리해두었습니다. 핵심은 **구체적이고 명확한 지시, 정보 순서의 활용, 안전장치 마련, 토큰 최적화**입니다.

---

## **1\. 프롬프트 구성 요소**

* **원칙**: 프롬프트를 **역할 메시지 단위**로 생각합니다.

  * **시스템 메시지**: 모델의 전반적 행동 지침 (“너는 수학 선생님이다”)

  * **사용자 메시지**: 사용자가 하는 실제 질문

  * **어시스턴트 메시지**: 이전 대화 예시나 답변

**예시 (Chat Completion API 스타일)**

* System: “너는 IT 전문가다. 항상 단계별로 설명한다.”

* User: “클라우드란 무엇인가?”

* Assistant(예시): “클라우드는 인터넷을 통해 서버, 저장소 등을 빌려 쓰는 서비스다.”

---

## **2\. 구체적이고 모호하지 않게**

* **원칙**: 애매하게 쓰면 AI가 추측에 의존해 버립니다. 원하는 작업을 **정확하게 제한**해야 합니다.

**예시**  
 ❌ “보고서를 작성해줘.”  
 ✅ “마케팅 보고서를 3문단으로 작성해줘. 각 문단은 5문장 이내, 불릿포인트 금지.”

---

## **3\. 자세하고 묘사적으로**

* **원칙**: 모델이 상황을 잘 이해할 수 있도록 배경과 스타일을 서술적으로 알려줍니다.

**예시**  
 ❌ “회의록 요약해줘.”  
 ✅ “당신은 전문 비서입니다. 아래 회의 내용을 읽고, 임원들이 이해하기 쉽게 **항목별 요약**을 작성하세요. 톤은 격식 있게 유지하고, 각 항목은 2문장 이하로 요약하세요.”

---

## **4\. 중요한 지시는 반복하거나 강조 (Double Down)**

* **원칙**: 모델은 앞이나 끝 부분을 더 잘 기억합니다(Recency bias). 중요한 지시는 **앞뒤에 두 번 강조**하는 것도 효과적입니다.

**예시**  
 “반드시 두 문장으로 요약하라.

### **원문: … (텍스트)…**

최종 답변도 반드시 두 문장으로만 작성하라.”

---

## **5\. 프롬프트 정보의 순서 고려**

* **원칙**: 정보와 예시의 순서가 결과에 영향을 줍니다.

* **팁**: 예시 순서를 바꿔 실험해보고, 어떤 배열이 가장 안정적인지 확인하세요.

**예시**

* 첫 번째 예시를 긍정적 내용으로 줄 경우 → 모델이 긍정적 답변에 치우칠 수 있음

* 부정적 예시를 뒤에 줄 경우 → 모델이 그 영향을 더 강하게 받을 수 있음

---

## **6\. 모델에게 “출구” 제공 (Hallucination 방지)**

* **원칙**: 모델이 모르면 그냥 “모른다”고 하도록 유도해야 합니다.

* **비유**: 학생에게 “답을 몰라도 아무 말이나 하지 말고 ‘잘 모르겠습니다’라고 해”라고 가르치는 것과 같아요.

**예시**  
 “아래 텍스트에 답이 없으면 반드시 ‘정보 없음’이라고 답하라.”

---

## **7\. 토큰 절약과 최적화**

* **원칙**: 프롬프트가 길면 비용과 속도에 불리합니다.

* **팁**:

  * JSON보다 **테이블 형식**을 쓰면 필드명이 반복되지 않아 토큰 절약 가능

  * 불필요한 공백, 기호, 장황한 표현 줄이기

**예시 (JSON 대신 테이블)**  
 ❌ JSON 형식:

{  
  "이름": "홍길동",  
  "나이": "25",  
  "직업": "개발자"  
}

✅ 테이블 형식:

이름 | 나이 | 직업  
홍길동 | 25 | 개발자

---

## **8\. Few-shot 예시 활용**

* **원칙**: 예시는 너무 많으면 오히려 혼란을 줄 수 있으니, 꼭 필요한 것만 선택하세요.

* **주의**: 최신에 제시된 예시일수록 모델이 더 강하게 따릅니다.

**예시**  
 “아래 예시처럼 답해줘.  
 예시 1: 질문: ‘사과 색깔은?’ → 답: ‘빨강’  
 예시 2: 질문: ‘바나나 색깔은?’ → 답: ‘노랑’  
 → 질문: ‘포도 색깔은?’”

---

# **✅ 최종 요약**

Microsoft의 Azure OpenAI 프롬프트 엔지니어링 핵심은 다음과 같습니다.

1. 프롬프트는 **시스템·사용자·어시스턴트 메시지**로 나눈다.

2. 애매하지 않고 구체적으로 작성한다.

3. 상황을 서술적으로 설명한다.

4. 중요한 지시는 앞뒤로 반복해 강조한다.

5. 정보와 예시의 **순서**에 주의한다.

6. “정보 없음” 같은 **안전 출구**를 제공한다.

7. JSON 대신 테이블 등으로 **토큰을 절약**한다.

8. Few-shot 예시는 **적당히, 최신 예시일수록 강하게 반영**된다.

이 원칙을 따르면 Azure OpenAI의 GPT 모델이 **더 정확하고 예측 가능한 답변**을 주도록 설계할 수 있습니다.
