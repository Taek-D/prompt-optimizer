# **📊 주요 기업별 프롬프트 엔지니어링 가이드 비교**

| 구분 | OpenAI | Google | Microsoft (Azure OpenAI) | Anthropic (Claude) | Meta (Llama 2\) |
| ----- | ----- | ----- | ----- | ----- | ----- |
| **핵심 철학** | 명확성 · 구체성 · 예시 | 구조화(역할→맥락→지시) · 단계적 해결 | 구성요소(시스템/사용자/어시스턴트) 기반 제어 | 헌법적 AI · 안전성 · 긴 맥락 처리 | 오픈소스 최적 활용 · 간결성과 신뢰성 |
| **주요 기법** | \- 최신 모델 사용- 지시는 맨 앞에- 구체적 요구사항- 출력 예시 제시- 단계별 접근(Zero/Few-shot) | \- Role → Context → Instruction 구조- 다양한 예시 제공- 출력 범위 제약- 단계 분해(Chaining)- 자기 검토 지시 | \- 프롬프트 구성 요소 활용- 구체적이고 모호하지 않게- 중요한 지시 반복(Double Down)- 정보 순서 고려- 안전한 출구(“정보 없음”) 제공 | \- XML 태그로 구분- 프롬프트와 출력 스타일 일치- 사고 과정 유도()- Few-shot 예시- Assistant 역할 미리 지정- 체인 구조 | \- 명확한 지시 \+ 제약 조건- 역할 프롬프트- 체인-오브-생각(CoT)- Self-consistency(자가 검증)- 외부 지식(RAG) 활용- 불필요한 말 제거 |
| **예시 강조** | 출력 템플릿 직접 제시 | 다양한 패턴 예시 3\~5개 | Few-shot 예시, 순서 주의 | 3\~5개 관련 예시 \+ Human/Assistant 포맷 | 3\~5개 관련 예시 \+ 일관성 검증 |
| **출력 제어** | JSON 등 템플릿 활용 | 제약 조건: “2문장 이내” | Recency bias 고려, 지시 반복 | 태그 기반 섹션 구분 | “군더더기 없이 핵심만” 규칙 |
| **특징적 장치** | Zero/Few-shot → Fine-tuning | Chain-of-Thought, 자기검열 | Double Down, “정보 없음” | XML 태그, Scratchpad, Thinking 단계 | Self-consistency, RAG |
| **적용 포인트** | 안정적이고 일관된 출력 | 체계적이고 단계적 문제 해결 | 예측 가능하고 안전한 출력 | 복잡한 긴 문맥 처리 강점 | 오픈소스+외부 지식 결합 최적화 |

# **✅ 요약 인사이트**

* **OpenAI** → **기본기**에 충실 (명확성, 구체성, 예시, 단계별 접근)

* **Google** → **구조화된 프롬프트 설계** (역할 부여 \+ 단계 분해 \+ 자기 검토)

* **Microsoft** → **실무 지향적** (메시지 구성 요소, Recency bias 고려, 안전장치 제공)

* **Anthropic(Claude)** → **긴 맥락과 태그 기반 사고 과정** (XML 태그, Thinking 단계)

* **Meta(Llama 2\)** → **오픈소스 최적화** (체인-오브-생각, Self-consistency, RAG 활용)
